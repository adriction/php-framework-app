JavaScript

assets/js/framework/components.js — un seul fichier, vanilla, sans dépendance. Piloté entièrement par des attributs data-* sur le HTML : rien à instancier côté app, un seul script chargé une fois dans templates/layout.html.twig ({{ asset('app.js') }}) suffit.

Tooltip, boutons, formulaires, cards, badges, table, pagination, avatar, spinner sont purement CSS et n'ont besoin d'aucun JS.

API

ComposantAttributs
Collapse (menu mobile navbar, panneau repliable)data-toggle="collapse" sur le déclencheur + data-target="#id" vers l'élément à basculer — bascule sa classe .show
Ongletsdata-toggle="tab" + data-target="#id" sur chaque .nav-link d'un .nav-tabs ; les panneaux ciblés doivent être frères sous un .tab-content
Modaldata-toggle="modal" + data-target="#id" pour ouvrir ; data-dismiss="modal" sur n'importe quel bouton à l'intérieur pour fermer. Fermeture aussi via Échap ou clic sur le backdrop
Alerte fermabledata-dismiss="alert" sur le .btn-close — retire l'élément .alert parent du DOM

Détails d'implémentation utiles

  • Modal : un seul backdrop (.modal-backdrop) est créé à la demande et réutilisé pour n'importe quel modal — pas besoin d'en déclarer un par modal dans le HTML. document.body.style.overflow est mis à hidden tant qu'un modal est ouvert.
  • Onglets : le groupe de liens actifs est déterminé par le .nav-tabs parent le plus proche du lien cliqué ; le groupe de panneaux par le parent direct du panneau ciblé — deux groupes d'onglets indépendants sur la même page ne se marchent pas dessus tant que chacun a son propre .nav-tabs/.tab-content.
  • Tout est branché via délégation d'événements sur document (un seul listener par type d'interaction) — fonctionne aussi pour du contenu ajouté dynamiquement au DOM après le chargement initial.

Étendre

Pas de mécanisme de plugin JS dédié : pour un nouveau comportement, ajouter un bloc dans components.js suivant le même pattern (délégation sur document, attribut data-* dédié) plutôt que d'introduire une dépendance externe.
